# 03 · 依賴注入（DI）

這份管：**新程式碼怎麼用 Koin**（annotation 風格、介面綁定、生命週期、qualifier、DI 圖驗證），以及「本專案只有一套 DI 容器」這條邊界。

這份不管，請看對應 owner：

> dispatcher 注入見 [11-coroutines-flow.md#hardcoded-dispatcher](11-coroutines-flow.md)
> ViewModel 不得持有 Android 型別見 [08-ui-state.md#context-in-viewmodel](08-ui-state.md)
> Composable 取得 ViewModel 的層級見 [09b-compose-state.md#viewmodel-in-reusable-composable](09b-compose-state.md)
> 模組依賴不得 `compileOnly(project(...))` 見 [02-modularization.md#no-compile-only-project](02-modularization.md)
> Repository 介面歸屬見 [04-domain-layer.md#repository-needs-interface](04-domain-layer.md)

**現況一句話**：本專案 DI 100% Koin（`koin-bom 4.1.0` + `koin-annotations 1.4.0`），**明確不採用 Hilt / Dagger**（[91-decisions.md](91-decisions.md) D-01）。新模組照 `libs/feature/presale_chat/src/main/kotlin/com/kkday/feature/presale_chat/di/PresaleChatModule.kt` 抄。

## 一、取得依賴的方式

### manual-impl-instantiation · MUST_NOT · new-only+on-touch · lint:manual-impl-instantiation

業務程式碼不得以 `XxxRepositoryImpl()` / `XxxUseCaseImpl()` / `XxxDataSourceImpl()` 直接建立實作類別；一律注入介面。

✗ `private val repo = OtpAuthRepositoryImpl(api)`
✓ `class SendOtpUseCase(private val repo: OtpAuthRepository)`  // 介面由 DI 提供

例外：`di/` 套件內的 Koin `@Module` 提供函式、測試碼。

### service-locator-get · MUST_NOT · new-only+on-touch · lint:service-locator-get

業務程式碼不得用 service locator 取依賴：`KoinJavaComponent.get<T>()`、`getKoin().get<T>()`、`GlobalContext.get()`。

✗ `val tracker = KoinJavaComponent.get<KKTrackTool>(KKTrackTool::class.java)`
✓ `class PresaleChatAnalyticsContext(private val tracker: KKTrackTool)`

例外：`di/` 套件內的定義、測試碼。容器邊界另見 [di-container-single-framework](#di-container-single-framework--must_not--new-onlyon-touch--manual)。
既有違規：`KoinJavaComponent` 35 處 → [90-migration-ledger.md#m-26](90-migration-ledger.md)

### inject-outside-whitelist · MUST_NOT · new-only · manual

`by inject()` 與 `KoinComponent` 只允許出現在由系統建構的類別：`Activity` / `Fragment` / `Application` / `Service` / `BroadcastReceiver` / `Worker`。其餘一律建構子注入。**Composable 內禁止 `by inject()`**，取 ViewModel 只能用 `koinViewModel()`。

✗ `class GetOrderUseCase : KoinComponent { private val repo: OrderRepository by inject() }`
✗ `@Composable fun OrderRoute() { val repo: OrderRepository by inject() }`
✓ `@Composable fun OrderRoute(viewModel: OrderViewModel = koinViewModel())`

例外：白名單類別（`attachBaseContext()` 早於 `onCreate`，該路徑取 `IResourcesProxy` / `ILocaleHelper` 只能用 `by inject()`）；Reductor reducer 觸碰時不主動改（見 M-01）。
既有違規：`by inject()` 758 處 / `KoinComponent` 218 類 → [90-migration-ledger.md#m-26](90-migration-ledger.md)

## 二、Koin module 的寫法

### koin-dsl-module · MUST_NOT · new-only · manual

新增的 DI 定義不得用手寫 DSL（`val xxxModule = module { single { ... } }`）。一律 annotation：自家類別用 `@Single` / `@Factory` / `@KoinViewModel`，第三方型別（Retrofit、OkHttp、Room、TapPay 等）用 `@Module` 類別內的 `@Single fun provideXxx()`。只有 annotation 路徑吃得到 `KOIN_CONFIG_CHECK` 的建置期驗證，也只有它能寫 `verify()` 測試。

✗ `val orderModule = module { single { OrderRepositoryImpl(get(), get()) } }`
✓ `@Module @ComponentScan("com.kkday.feature.order") class OrderModule { @Single fun provideX(): X = X() }`

例外：既有 DSL module 不主動改寫；觸碰時把該檔案的定義往 annotation 收斂。
既有違規：64 個 DSL module → [90-migration-ledger.md#m-26](90-migration-ledger.md)

### componentscan-too-broad · MUST · new-only · manual

`@ComponentScan` 的參數必須是該 Gradle 模組自己的 package 前綴，且不得與其他模組的掃描範圍重疊。禁止 `@ComponentScan("com.kkday")` 這種全域掃描。

✗ `@ComponentScan("com.kkday")`
✓ `@ComponentScan("com.kkday.feature.presale_chat")`

例外：無。
既有違規：`:app` 與 `:data:networking:api` 兩處都掃 `"com.kkday"` → [90-migration-ledger.md#m-26](90-migration-ledger.md)

### koin-binds-missing · MUST · new-only · manual

綁定介面時必須顯式宣告對外暴露的型別，不得只宣告實作型別卻在注入端要求介面。

✗ `@Single class OrderRepositoryImpl(...) : OrderRepository`
✓ `@Single(binds = [OrderRepository::class]) class OrderRepositoryImpl(...) : OrderRepository`

例外：只被自己模組內部以具體型別注入的類別。

### di-module-in-app · SHOULD · new-only · manual

DI module 檔案必須放在「提供該綁定的 Gradle 模組」內（慣例 `<module>/src/main/.../di/`）。`:app` 只保留 app 自身綁定與 `startKoin` 組裝。

✗ 在 `app/src/main/java/com/kkday/member/di/RepositoryModule.kt` 新增 feature 模組的 Repository 綁定
✓ 在 `libs/feature/order/.../di/OrderModule.kt` 宣告，再加進 `startKoin { modules(...) }`

例外：跨模組共用又沒有自然歸屬的第三方型別（`OkHttpClient`、`Retrofit`、`CoroutineScope` 等 app 級單例）留在 `:app` 或對應的 `:data` / `:libs` 模組。
既有違規：`:app` 20 個 DSL module，`startKoin` 一次載入 59 個 → [90-migration-ledger.md#m-26](90-migration-ledger.md)

## 三、生命週期與 qualifier

### usecase-as-single · MUST_NOT · new-only+on-touch · manual

UseCase 一律 `@Factory`（unscoped），不得綁成 `@Single` / `single {}`。

✗ `@Single class GetCreditCardListUseCase(private val repo: CreditCardRepository)`
✓ `@Factory class GetCreditCardListUseCase(private val repo: CreditCardRepository)`

例外：無。UseCase 不得持有狀態，見 [04-domain-layer.md#usecase-mutable-state](04-domain-layer.md)。

### single-for-stateless · SHOULD_NOT · new-only · manual

不得為了「少建幾個物件」而用 `@Single`。只有兩種情況才 `@Single`：持有需跨畫面共用的可變狀態（in-memory 快取、`MutableStateFlow`、DB/DataStore 連線包裝），或初始化成本高昂且被廣泛使用（OkHttp、Retrofit、Room）。無狀態的 Mapper、Formatter、純轉發 Repository 一律 `@Factory`。**ViewModel 一律 `@KoinViewModel`，不得改標 `@Single`** —— 那會讓狀態跨畫面共用且永不釋放。

✗ `@Single class OrderPriceFormatter`  // 無狀態
✗ `@Single class OrderViewModel(...)`  // ViewModel 綁成單例
✓ `@Factory class OrderPriceFormatter` / `@KoinViewModel class OrderViewModel(...)`
✓ `@Single fun provideOkHttpClient(): OkHttpClient`  // 初始化昂貴

例外：選 `@Single` 時必須在 PR 描述寫出屬於上述哪一種。

### koin-named-string-literal · SHOULD_NOT · new-only · manual

`named(...)` / `@Named(...)` 的 qualifier 不得寫字面字串，必須引用集中定義的常數（`com.kkday.data.consts.KoinConstant`，網路層用 `KKNetworking`）。要新的 qualifier 就先去該 object 加一個 `const val`。

✗ `@Named("DispatcherIO") private val dispatcher: CoroutineDispatcher`
✓ `@Named(KoinConstant.APP_IO_SCOPE) private val applicationIOScope: CoroutineScope`

例外：無。注意 `org.koin.core.annotation.Named` 與 `javax.inject.Named` 同名，勿誤 import（本專案沒有 `javax.inject`，誤 import 會直接編譯失敗）。
既有違規：`named()` 83 處 + `@Named` 15 處；`"DispatcherIO"` 在 `CoroutinesScopeModule.kt` / `UseCaseModule.kt` 仍是字面字串，`KoinConstant` 尚未收錄 → [90-migration-ledger.md#m-26](90-migration-ledger.md)

### koin-scope-not-closed · MUST · new-only · manual

手動 `getKoin().createScope(...)` 建立的 scope 必須在所有路徑（含例外）`close()`。畫面級 scope 一律改用 `AndroidScopeComponent` + `activityScope()` / `fragmentScope()`，由框架自動關閉。

✗ `val scope = getKoin().createScope<OrderActivity>()`  // 無對應 close()
✓ `class OrderActivity : AppCompatActivity(), AndroidScopeComponent { override val scope by activityScope() }`

例外：無。專案目前 Koin scope 使用數為 0，新增前先確認真的需要 scope 而非 `@Factory`。

## 四、DI 圖驗證

### koin-config-check-off · MUST_NOT · new-only · manual

使用 koin-annotations 的模組不得把 KSP 參數 `KOIN_CONFIG_CHECK` 設為 `"false"`。這是 Koin 唯一的建置期驗證管道，關掉等於缺漏綁定只能等使用者進畫面才 crash。

✗ `ksp { arg("KOIN_CONFIG_CHECK", "false") }`
✓ `ksp { arg("KOIN_CONFIG_CHECK", "true") }`

例外：無。撞到既有重複綁定時修綁定，不是關檢查。
既有違規：3 個模組（`libs/feature/chat`、`libs/feature/hotel/product`、`libs/feature/presale_chat`）→ [90-migration-ledger.md#m-26](90-migration-ledger.md)

### koin-module-not-verified · MUST · new-only · manual

**新增 `@Module` 類別、或在既有 `@Module` 新增綁定的 Gradle 模組，必須有一支 JVM 測試呼叫 `verify()`**，且該模組的 `KOIN_CONFIG_CHECK` 必須為 `"true"`。`verify()` 在 JVM test 就能抓出缺漏／重複綁定，不必等 runtime crash。禁止用 Koin 4 已 deprecated 的 `checkModules()`。

```kotlin
import org.koin.ksp.generated.module   // 產生 XxxModule().module
import org.koin.test.verify.verify     // 需要 testImplementation("io.insert-koin:koin-test")

@Test fun verify() = OrderModule().module.verify(extraTypes = listOf(Context::class))
```

無法靜態推導的型別（`Context`、runtime 參數）放進 `extraTypes` 白名單，不得整體跳過測試。
前置（一次性，第一支 verify 測試的 PR 順手做）：`gradle/libs.versions.toml` 加 `koin-test = { group = "io.insert-koin", name = "koin-test" }`（版本由 `koin-bom` 帶），在 `build-logic` 的 `configureDI` 對套用 koin-annotations 的模組加 `testImplementation`。編譯器若要求 opt-in 就加 `@OptIn(KoinExperimentalAPI::class)`。
既有違規：3 個關閉 `KOIN_CONFIG_CHECK` 的模組（chat、hotel/product、presale_chat）＋ DI 解析測試覆蓋 1/83 → [90-migration-ledger.md#m-26](90-migration-ledger.md)。觸碰這些模組的 DI 檔案時，順手打開檢查並修掉重複綁定。

## 五、不採用的 DI 框架

**本專案不採用 Hilt。** 寫 `@InstallIn`／`@HiltViewModel`／`@AndroidEntryPoint`／`hiltViewModel()`／`javax.inject.Inject`（以及 dagger 的 `@Module`／`@Provides`）都會編譯失敗 —— 專案沒有 Hilt gradle plugin、沒有 `javax.inject`，`gradle/libs.versions.toml` 的 `dagger 2.48.1` 是零引用的殘留宣告。注意本檔第二節的 `@Module` 指的是 `org.koin.core.annotation.Module`，兩者不同。Koin 的對應寫法見第二、三節；不採用的完整理由（含兩項永久性架構阻礙）見 [91-decisions.md](91-decisions.md) D-01。

### di-container-single-framework · MUST_NOT · new-only+on-touch · manual

本專案 DI 容器只有 Koin，不得引入第二套 DI 框架（Hilt / Dagger `@Component` / `javax.inject` 建構子注入 / 自製 service locator 單例），也不得寫跨框架橋接程式碼。一個型別只能由一個容器擁有。Koin 容器 API（`startKoin`、`loadKoinModules`、`KoinJavaComponent.get()`、`getKoin().get()`）只允許出現在 `:app` 的 `di/` 套件內；feature 模組內一律零 service locator。

✗ `object ServiceRegistry { val orderRepo = KoinJavaComponent.get<OrderRepository>(OrderRepository::class.java) }`（自製容器）
✗ 在 `libs/feature/order/` 內呼叫 `getKoin().get<OrderRepository>()`
✓ `@Factory class GetOrderUseCase(private val repo: OrderRepository)`（建構子注入）

例外：無。`libs.versions.toml` 的 `dagger` / `dagger-compiler` 條目零引用，不得新增引用（應於清理 PR 刪除）。
既有違規：`KoinJavaComponent` 35 處 → [90-migration-ledger.md#m-26](90-migration-ledger.md)

### hilt-before-prerequisites · MUST_NOT · new-only · manual

**任何模組都不得寫 `@HiltAndroidApp` / `@AndroidEntryPoint` / `@HiltViewModel` / `@InstallIn` / `hiltViewModel()` / `javax.inject.Inject`。** 這不是「等前置條件」，是本專案評估後不採用（[91-decisions.md](91-decisions.md) D-01）：其中 base class 建構子參數與 `attachBaseContext()` 時序兩項阻礙是永久性的。

✗ `@HiltViewModel class OrderViewModel @Inject constructor(...)`
✓ `@KoinViewModel class OrderViewModel(private val getOrder: GetOrderUseCase)`

例外：無。看到既有程式碼有 Hilt 註解 = 它根本沒編譯過，直接改成 Koin。
