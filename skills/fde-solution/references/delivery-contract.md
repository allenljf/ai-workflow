# Delivery contract

Create one maintained contract containing problem/non-goals, business owner, data owner, current baseline, acceptance cases and thresholds, identity/permissions, cost/deadline, support owner and rollback. State which fields remain unknown and who must decide them.

Choose a representative set and an independent holdout. Test rejection and failure paths as well as success. For each observed result retain commit, dataset hash, provider/model version, environment, run time, report path/hash and acceptance IDs. A cached or missing artifact is not current evidence.

A fixture validates interfaces. A local model run observes that model and hardware. Enterprise adoption requires a real pilot and a human decision scoped to its profiles. A company-approved workflow is not inferred from a public guide or vendor benchmark.

Before handoff, show what the recipient can reproduce, how to resume interrupted work, known limitations, safe rollback and responsibility for operational alerts. Follow the user's existing approvals; ask only for genuinely missing decisions or external side effects outside the authorized scope.
