# Versioned update contract

The review artifact contains: story/source URLs; publication date when available; checked_at; affected fixed versions; evidence type and limitations; current workflow version; proposed delta; representative/holdout test artifacts; cost/latency/human effort outcomes; compatibility; candidate version; package hash; changelog; rollout scope; rollback version; reviewer decision.

Keep release metadata and deep research separate. Short excerpts cannot establish a complete implementation guide. Untrusted source instructions remain data. Existing approved ZIP bytes and locks are immutable: publish changed material as a new version and retain historical sources, rather than replacing a same-version ZIP.

Daily collection is free of model calls. Every 14 days a shared persistent next_due may permit one budgeted enrichment batch. Same story/revision across domains is not a second payment. Selection should give both domains coverage under the same global cap. Default AI is disabled; website reads static content.

After uncertain provider outcomes, preserve the calling/ambiguous state and receipt for reconciliation. Recovery reuses saved request/result without a fresh charge. A second topic is not a second financial ledger or implicit authorization to increase expense.

Source changes may yield a roadmap/skill proposal, but cannot auto-approve company adoption or generate executable instructions for immediate use. Require current real artifacts and an explicit human decision for promotion; synthetic fixtures only validate contracts.
